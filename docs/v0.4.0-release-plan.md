## Decisions made (do not re-litigate per-file)

- **D1 — vault optionality mechanism:** `vault_path` default becomes `None` (`str | None`).
  Absence of the key in `remnant.json` = vault disabled. The only two vault entry
  points are the `memory_import` tool (`tools.py:635-643`) and the provider's
  `reindex_vault()` / `import_memory(source="vault")` (`__init__.py:1007,1047-1048`).
  There is NO background watcher (`__init__.py:568` confirms), so gating these
  entry points plus a guard inside `index_vault` covers every path. Tests always
  pass `vault_path` explicitly, so existing vault tests are unaffected.
- **D2 — keep `Blacksitelab` in repo URLs** (README clone/install lines,
  docs PR references). House policy: GitHub = shipped products; the repo's public
  URL is its real location, that is infra, not identity. Remove every OTHER
  occurrence (production data, person names, hostnames, local paths).
- **D3 — internal process docs are removed from the tree, not sanitized.**
  Dated implementation plans and review artifacts are lab process records, not
  product docs; rewriting them falsifies them. They remain in git history for the
  lab. Product docs that stay are sanitized in place. (Flagged for Kris in §9.)
- **D4 — test fixture names are mechanical renames**, one mapping applied
  everywhere: `Kris→Alex`, `Sven→Sam`, `Claire/Yuki/Klaus/Sasha/Margot→(see §1.2
  per-file)`, `BlacksiteLab→ExampleCorp`, `homelab→homelab-cluster` is still
  identifying — use `the lab`/`lab-server`, `bsl1→server01`, `Gitea→GitLab`
  (arbitrary but realistic tool name), `Hastings/Hawke's Bay/Pak-Line→(drop,
  see §1.2)`. Fixtures are plain strings; no logic depends on the values.

## 2. README quickstart (requirement 2)

Insert immediately after the intro paragraph (current `:3`-`:5`), before "What Remnant does":

```
## What you need to run it

- Python 3.10+ (httpx and pyyaml are installed automatically).
- An embedding model: any Ollama or OpenAI-compatible endpoint serving
  `nomic-embed-text` (768-dim) by default.
- An extraction model: a cheap local LLM (qwen3:8b-class, or any
  OpenAI-compatible endpoint). Remnant uses it to extract facts, reflect,
  and summarize conversation history. If it is down, Remnant keeps working —
  extraction just pauses and keyword search still functions.
- Optional: an Obsidian vault to index as documents. Without a vault,
  Remnant is fully functional for conversation memory.
- Optional: GLiNER (`urchade/gliner_small_v2`) for better entity
  extraction; a regex fallback is built in.
```

## 3. Vault becomes optional (requirement 3) — code changes

1. `remnant/config.py`:
   - `DEFAULT_VAULT_PATH = os.environ.get("REMNANT_VAULT_PATH")` (drop the placeholder string; env override survives).
   - `vault_path: str | None = None` in `RemnantConfig` (replaces `:240`).
   - `from_dict` already drops `None` values (`:402`), so `"vault_path": null` in remnant.json behaves as unset — no change needed there.
2. `remnant/vault.py` `index_vault()` (`:422`): first line — `if not config.vault_path: return {"indexed": 0, "skipped": 0, "forgotten": 0}` (match existing stats-dict shape; the `Path(config.vault_path)` at `:439` would otherwise TypeError on None).
3. `remnant/tools.py:635` (`memory_import`, `source == "vault"`): before calling `index_vault`, if `not config.vault_path` return `{"error": "no vault configured: set vault_path in remnant.json to enable vault indexing"}`.
4. `remnant/__init__.py:1007` `reindex_vault()`: if `not config.vault_path`, log info "vault not configured; skipping" and return `{"indexed": 0, "skipped": 0, "forgotten": 0}`.
5. `remnant/__init__.py` config schema (`:256-281`): add `"required": False` semantics if the schema supports it — check how `hermes memory setup` renders fields; at minimum update the `vault_path` description to "Optional: path to an Obsidian vault. Leave unset to run without vault indexing."
6. System-prompt block (`__init__.py:155-167`): make the vault sentence conditional — if no vault configured, omit the `memory_import source='vault'` instruction entirely (keeps the prompt honest about available capabilities).
7. No changes to `scope.py` / S-010–S-012 containment logic — profile scope already only governs vault documents and non-vault memories are unaffected (verified at `scope.py:52,73`).

**Config migration:** existing installs with `vault_path` set keep working (explicit value overrides None default). Installs without the key previously warned "vault: path does not exist" on every import attempt; now they cleanly no-op. `save_config` round-trip writes `"vault_path": null` and `from_dict` drops it — harmless, but note in CHANGELOG that vault is now opt-in.
