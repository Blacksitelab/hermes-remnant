## Chosen interface (new; not an existing API)

Add one explicit model-facing tool, memory_history, in tools.py. Do not add automatic date intent detection to prefetch or another per-turn LLM. The host model already interprets user questions; tool schema describes when to use history instead of durable-fact search.

Inputs:
- query: optional topic/project terms or historical question, max 1000 characters.
- start, end: optional ISO dates or offset-aware ISO datetimes. start inclusive; end exclusive. A start DATE without end means that local calendar day. Datetime start without end is invalid. Explicit end without start is allowed (older history).
- relative: optional one of today, yesterday, last_week, or positive duration Nh/Nd/Nw. Mutually exclusive with start/end. last_week = preceding Monday 00:00 through current Monday 00:00 in the selected zone; durations = rolling elapsed time. Document the distinction.
- timezone: optional valid IANA zone, falling back to config.history_timezone, default UTC. Always echo the actual zone and resolved UTC bounds. Never silently infer a machine fixed offset as an IANA zone. Missing year is not parsed: the host must establish it from context or ask the user. Reject invalid dates, reverse ranges, naive datetimes and unknown zones without archive/model calls. Use datetime + zoneinfo; local date boundaries are separately constructed midnights, NOT start+86400 seconds.
- session_id: optional exact source session to inspect; around_message_id: optional positive integer to expand a known anchor in that session. Both remain subject to the same owner and visibility gates.
- cursor: optional bounded continuation token for discovery/messages. It contains validated keyset/offset state and a normalized request+owner fingerprint, never a filesystem path or grant of authority. Reapply authorization on every page. Reject changed request/owner, malformed/oversized tokens.
- synthesize: boolean, default true. False returns bounded evidence only, no request-time model call.
Require a query, time selector, or session_id; do not accidentally launch whole-archive synthesis from empty arguments.

Return a JSON object:
- status: ok | partial | no_evidence | unavailable | invalid_request | disabled.
- resolved_range: timezone/start_utc/end_utc/reference_now (relative clock captured once).
- sessions: bounded metadata, source='interactive' or actual automation source, source session IDs and native @session:<profile>/<id> links; topics/statements retain their own sources.
- statements: objects {topic, text, kind, uncertainty, sources}. kind is discussion | decision | proposal | abandoned | correction | unresolved | conflict. sources are exact {session_id, message_id, timestamp, role} references; never short IDs or Remnant turn IDs pretending to be Hermes IDs.
- evidence: bounded raw excerpts or validated cached-summary evidence with source references, truncation flag, and context-only/outside-range flag where applicable.
- coverage: discovery_complete, summaries_used, summaries_missing_or_stale, sessions_matched_on_page, sessions_expanded, messages_available_on_page (null if not measured), messages_returned, content_truncated, omitted_due_to_budget, index_incomplete, reason. A bounded page is not full history. Unknown totals are null, never made-up zero/100%.
- next_cursor, has_more, warnings, elapsed_ms, token_estimate. has_more must agree with actual continuation evidence; deadline interruption is partial/unknown coverage, not no evidence.
- synthesis is a deterministic rendering of validated statements, not unchecked model prose. Explicit no-evidence text says no evidence was found in the searched accessible coverage, never 'we never discussed it'.

Keep memory_reflect/search unchanged. Add a short static tool-routing sentence to the provider prompt: history questions use memory_history, dates require explicit year/zone, disclose incomplete coverage. This is a constant capability description, not per-turn historical context expansion.

## Retrieval algorithm and bounded coverage

1. Resolve/validate selectors and owner before any model work; take one reference clock for relative time and continuation. Check the summary cache first for authorized matching sessions/topics and source freshness. Summaries guide which windows to expand; they cannot restrict timestamp discovery to indexed sessions.
2. Date/range lookup enumerates every eligible session with at least one visible message satisfying start <= messages.timestamp < end. Session starts alone cannot exclude candidates, including sessions started the prior day or messages imported late. Use indexed per-session EXISTS and stable (started_at,id) keyset pages, with bounded metadata scanning and continuation. Initial limits: at most 200 session candidates scanned, at most 20 matched sessions presented per call. Read one extra candidate to determine continuation, or return an explicit interrupted scan position. No unbounded fetchall, count(*) across all raw content, or scan inside ordinary turns. Repeated pages must recover all matches on a stable test archive; no ranking cap may erase date matches.
3. Topic-only/project history: combine compact-summary matches with Hermes SessionDB.search_messages for source discovery. Do not pass Hermes session-start bounds as message-time truth. Use projections, bounded pages (at most 100 hits per call), reauthorize results, preserve independent topic/session groups, and expose lexical/index gaps and continuation. Query terms are hints, not guaranteed semantic recall. A query plus date narrows within timestamp-selected sessions; the question's boilerplate/date words must not become mandatory FTS terms. Summary misses never veto raw matches. If FTS is absent/rebuilding, bounded visible raw-text fallback plus honest partial/index status is required.
4. Expand selected summary references or raw topic anchors in small local windows (initially +/-2 messages). On a plain date overview distribute raw fallback across sessions rather than letting the first long session exhaust the budget. Initial global cap: 80 raw messages per call, 2000 chars per excerpt; always SQL-bound projected content. User/assistant context outside a date range may clarify an in-range reference only when explicitly labelled; do not silently claim an out-of-range decision happened on that date.
5. Long-session and unknown-summary cases remain navigable via message continuations/session+anchor. Deduplicate exact source IDs. Keep raw ownership/session IDs even when presenting compression lineage; do not blindly combine reset/delegation branches. If equivalent replay rows are deduped, retain provenance and disclose uncertainty rather than inferring they are independent confirmations.
6. Optional synthesis makes at most ONE llm.chat call per explicit history request using reflect endpoint/model. No map/reduce fanout, autonomous cursor loop, embedding call or query-rewrite model. Input includes bounded original evidence, summary status/coverage and question. Structured output requires topics/statements/status/source references. Validate shape, lengths, allowed statuses and that every reference is in evidence actually supplied, in the correct session and authorized. Reject fabricated IDs and unsupported references. Model language with valid citations is still not semantically proven: mark paraphrases as model-derived/uncertain and show evidence. Citation validation is not a claim of infallibility.
7. Tell the model to preserve proposals vs adopted decisions, chronological corrections, withdrawn/abandoned choices, conditions and unresolved alternatives. Never let 'latest wins' erase conflicting evidence across topics/sessions. Invalid output, model timeout or outage returns a deterministic source-linked extractive fallback with uncertainty and coverage; never silently return authoritative unsupported prose. Zero evidence means zero model calls.

Initial hard safety ceilings (configuration may lower, not raise beyond these without code/tests): SQL/discovery deadline 3 seconds per request, request model timeout 30 seconds, full model input 5500 estimated tokens including prompt/question/metadata, model output 1024 tokens, fully serialized tool output 4000 estimated tokens. Preserve valid JSON/provenance/coverage by dropping whole entries, not slicing serialized JSON. Validate CJK/Unicode and oversized question/source/output; describe token estimates honestly if the deployment tokenizer is absent. Reuse the existing token-counter hook when available. SQL cancellation returns partial/unavailable rather than false completeness. End-to-end latency includes the explicit model timeout; do not market 3 seconds as a full synthesis deadline.

## Asynchronous summaries and persistence

Add config.history_enabled (default true), history_timezone (UTC), history_summary_enabled (default true). Safety budgets above can be constants for now, not a configuration framework. Disabling history removes tool work and boundary enqueue; disabling summaries leaves raw recall usable. Summary requests use existing extract transport/model, with the same 5500 input / 1024 output ceilings and at most one call per attempt.

Proposed additive schema 18 table history_summaries, primary key (archive_key, agent_id, session_id):
- archive_key: digest of canonical trusted archive path (not an access grant), agent_id, session_id.
- source_version: compact session fingerprint including relevant source metadata/count/max ID and rewind/activity markers; source reference validation still required because count/max ID alone misses edits.
- summary_json: validated bounded topic/statement records with message references; maximum 12000 UTF-8 bytes, maximum 8 topics, 24 statements. Never whole source messages or prompts. Each stored reference includes a short content digest for revalidation.
- coverage_json: capped to 2000 bytes, records bounded message/input coverage, source count when known, omitted/truncated state; never 'complete' on sampled input.
- status (pending/running/ready/retry_wait/dead_letter), attempts, available_at, claimed_at, updated_at, error_code (short categorical code only).
One row per session/owner, replace in place; no revision archive, embeddings, full-text duplicate or extra transcript table. Queue and result share the row, so missing/failed summaries cannot create separate unbounded queues.

Hard caps: 1000 total history_summaries rows across the shared DB (including pending/dead letters), at most 64 queued/running jobs per owner, three attempts per source version, at most 20 summary model attempts per owner per UTC day. Enforce caps and claims transactionally across processes; daily call reservations must be durable/atomic (reuse owner-scoped dream_state counters or another existing bounded state mechanism, not lossy buffered telemetry). A failed attempt consumes budget. Prune oldest disposable non-running rows and reject enqueue if only active rows occupy capacity. No source data deletion. New archive/owner combinations cannot bypass the global row cap. Honor lease recovery and don't evict a running row to duplicate its model call.

on_session_end and a genuine session switch enqueue the old session ID only; do not copy hook messages, read archive contents, or call a model in hooks. Exclude delegated/non-primary contexts. Queueing is idempotent/coalesced; flush races/missing archive rows lead to bounded retry, then raw fallback. Register one optional callback with ExtractionWorker to process at most one summary job after extraction work, never overlapping that worker's model calls. No automatic full-archive sweep at startup. Historical queries may enqueue a bounded set of missing/stale matched sessions for later processing, but do not wait for their summaries. Callback runs only when a historical job exists; ordinary turns create none. Ensure a long extraction backlog doesn't lead to unbounded historical draining.

Initial model summary covers bounded source windows only. Do not summarize a huge session's first 5500 tokens then label the whole session covered. Capture first/last and relevant existing anchors within the fixed budget and retain omitted coverage; later requests expand raw windows to handle absent topics. No rolling recursive summary that silently replaces unobserved evidence.

Add history_summaries to recover.py's disposable projections; do not attempt to migrate external numeric message IDs into Remnant IDs. Existing v17 stores migrate additively with memories/turns/claims unchanged. Any schema introspection/table lists in tests/maintenance need matching updates.
